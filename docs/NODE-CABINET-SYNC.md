# Node ↔ Cabinet contract

**What this is.** The cabinet (`cabinet/`) and the node (`node/`) live in
one repository now and ship from one `npm run pack`, but the deployed
cabinet at https://lit-games-cabinet.vercel.app reads whatever node its
visitor points it at — including nodes running an older zip. So the
contract below is enforced by a test, not by a note: `demo/cabinet.test.mjs`
boots a node and asserts every field the cabinet reads, by name and type.
Change the node, run `npm test`, and a break shows up before a redeploy.

History: this file began as the handoff from the cabinet build (17 Sep 2026)
to the node side. Sections 2–6 of that handoff are resolved below with the
resolution stated; what remains open is in §3.

---

## 1. What the cabinet reads

### 1.1 Base URL

`localStorage['cabinet.nodeUrl']`, defaulting to `config.js NODE_URL`
(`http://127.0.0.1:7801`). **Open:** the public https seed (§3.1). Until it
exists, the hosted cabinet shows real data only to someone with a local
node; a LAN address will not work from an https page (mixed content).

### 1.2 Headers

Every response, including the `OPTIONS` preflight: `Access-Control-Allow-Origin: *`
and `Access-Control-Allow-Private-Network: true`. Asserted by the test.

### 1.3 Endpoints and fields — the load-bearing list

Polled every 5 s (`/deltas` every 15 s), read-only, no auth. The test asserts
every name below.

| Endpoint | Fields read by name |
|---|---|
| `GET /health` | `nodeId operator roles region addr epoch peers rulesets{rulesetId: buildHash} buildsHeld staking bonded chain.{offline,rpc,head,lastError} startedAt uptimeMs` |
| `GET /peers` | `peers[].{nodeId operator addr region roles fresh bonded clockSkewS rulesets}` |
| `GET /snapshot` | `epoch peers[] manifests{rulesetId: {buildHash, services, …}} root staking` — the fold uses `manifests[rid].services`; placement verification uses `peers` and `root` |
| `GET /leaderboard?ruleset=` | `rulesetId deriveVersion digest skipped leaderboard[].{rank player rating}` |
| `GET /stats?ruleset=` | `{playerId: {matches wins ticks}}` |
| `GET /deltas?ruleset=` | `deltas[].{matchId rulesetId buildHash mode participants teams? scores ticks hostId cosigners settledAt epoch attestation}` |
| `POST /queue`, `GET /match?playerId=` | through `cabinet/client.js` — the same file `demo/client.test.mjs` runs |

### 1.4 Player identity

An ed25519 keypair under `localStorage['litnode.player']` (`cabinet/client.js`,
`IDENTITY_KEY`), the same key the node-served page and the tests use; a key
made under the cabinet's earlier name `cabinet.identity` is migrated once.
The public key is the `playerId` in every queue entry, ledger signature and
ladder row. Without WebCrypto (plain http from a LAN address) there is no
key: the cabinet says so and stays read-only. Binding the key to a
wallet-owned profile is `docs/WALLET-IDENTITY.md`.

### 1.5 Ruleset identifiers in `cabinet/config.js`

| title | `rulesetId` | `buildHash` |
|---|---|---|
| Agent Fighter | `agent-fighter.v1` | `859e7215418db6473f0ceb1a88a1f51dc279db1974636c2262f547fcafca76da` |
| Pickle Brawl | `pickle-brawl.v1` | `db035b782d23e85d4dcfdab0b2364f9e4f1c828b3dd8b2217c25b62cf0e1cb2e` |
| Robot Fighting Championship (AFC) | *(none yet)* | *(none yet)* |

A rebuilt ruleset changes its hash; update `config.js` to what `/health.rulesets`
advertises or the "on the mesh" panel shows a stale hash (cosmetic — the
node pins by hash regardless).

### 1.6 Protocol modules the cabinet runs

`cabinet/protocol/` is generated by `npm run vendor:cabinet` from
`protocol/` and pinned in `MANIFEST.json`; the test fails on drift. Never
edit the copies.

## 3. Open

### 3.1 A public https seed

The single change that makes the hosted cabinet show the real mesh to any
visitor: a tunnel or reverse proxy in front of the desktop's 7801,
`PUBLIC_ADDR=https://…` in its `node.env`, and that URL as `NODE_URL` in
`cabinet/config.js`, then redeploy. Zero-cost path: a Cloudflare tunnel, the
same mechanism the Agent Fighter relay already uses.

### 3.2 A title that consumes `cabinet:init.match` — sprint 1

The cabinet places a match and launches against the drawn host's relay
(`?ws=` for Agent Fighter, the descriptor for everyone). Nothing joins that
room yet. For Agent Fighter:

1. The client reads `init.match` (or `?ws=` + `?match=`) and joins that relay
   room as `init.player.id` — the ed25519 key — instead of a display name.
2. The relay writes ledgers keyed by those ids; `af-watch` (or the relay
   itself, `POST /ledger`) submits `participants` as player keys. Deltas
   then land on the cabinet's ladder under the key that queued.
3. The client signs the chain head at match end (`protocol/log.js ledgerBody`,
   `LEDGER_TAG`) so the delta settles `attestation: 'players'`.

Acceptance: a match started with *Find match* appears in that player's
record on the cabinet, co-signed by a node under another operator.

### 3.3 Pickle Brawl online and AFC — sprint 2

Pickle Brawl's online surface (`picklebrawl.live`) has no settlement path;
an attested report from its server is the cheap route and the adapter
exists. AFC needs a ruleset: its engine is deterministic and re-simulating,
which is the `defineTitle` shape — bundle it with `tools/bundle-ruleset.mjs`.

### 3.4 AIR / wallet sign-in inside the iframe

The framed titles' own AIR sign-in is blocked by their `frame-ancestors`.
The cabinet-side answer is `docs/WALLET-IDENTITY.md`: the cabinet owns
identity and hands it to the title over the SDK, so the title never needs
to sign in inside the frame. Independently, ask AIR to allowlist
`lit-games-cabinet.vercel.app` (and the custom domain) for the interim.

## 4. Rules

- A field the cabinet reads by name is never renamed; new fields are added
  beside it. Add every new read to `demo/cabinet.test.mjs` in the same
  change.
- `cabinet/protocol/` is generated. `npm run vendor:cabinet` after any
  change to a vendored module; the test tells you which.
- The cabinet's `config.js` is the one file to edit for roster, addresses
  and the default node URL.
