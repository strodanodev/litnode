## 3. What to do, in order

**P0 — patch 0.12.5 (pilot condition; all reachable through a public tunnel URL today)**

1. **`update.cmd` bypasses ReleaseRegistry** (`tools/update.mjs:23` builds the updater with no `registry`;
   `node/update.js:122` then returns ok). A leaked release key plus GitHub write access ships code to every operator
   who uses the documented manual path. Pass the chain's `statusOf`, fail closed.
2. **Key rotation is applied before the registry gate** (`node/update.js:172-173`): a manifest signed by a leaked key
   can add its own key and retire the pinned one. Honour `rotateTo`/`retire` only from a registry-active release.
3. **Casual `/ledger` intake** (`node/litnode.js:1641`, `node/settle.js:343-345`, `node/sandbox.js:43-44`): any
   `signatures` field skips the unsigned budget, replay runs before signatures are checked, the sandbox wait queue is
   unbounded, and settled casual ledgers (up to 4 MB) are never pruned. Behind the tunnel every caller is
   `127.0.0.1`, so the budget is shared. Verify before replay, cap the queue, key the budget on the forwarded client
   address, give unplaced casual results a TTL.
4. **Witness adverts** (`node/litnode.js:1160`, `:1173-1189`): up to 1,024 unauthenticated adverts per gossip message
   each start a fetch to an address that may be loopback or LAN, with unbounded response bodies and no concurrency
   cap. Require a bonded heartbeat at that address, cap concurrency and size, refuse private ranges.
5. **Browser CSRF on `POST /update` and `POST /chat`** (`node/litnode.js:1767-1776`, `:1594`): no Origin check,
   unlike `/restart`; CORS is `*` with private-network allowed (`:66`). Any page the operator opens can roll the node
   back and restart it.
6. **`/air/bond` is open to any AIR account** (`node/litnode.js:1811-1816`) and `commitIfHost` commits any adopted
   descriptor naming this node without the beacon and id checks (`:1285-1311`): the first squats an unbonded node's
   bond, the second lets one bonded key spend a host's gas. Loopback-gate the first; run `verifyDescriptor` in
   `absorbMatch`.

**P1 — before strangers (stage B)**

7. **The AIR token is a bearer credential given to whichever seed the arcade picked** (`cabinet/air.js:83,96`;
   `node/litnode.js:1797-1823`; `node/air.js:66-80`: no audience, no nonce). A stranger's seed can replay it to the
   custody node: bind its key to the victim's profile, or `transfer` the victim's title through `/air/publish`.
   Sign each request with the player key over a node-issued nonce.
8. **`cabinet:init` posts the AIR email and address to every framed title with target `'*'`** (`cabinet/app.js:1596`),
   including peer-gossiped third-party titles; iframes carry no `sandbox`. Send `air` only to `login: 'arcade'`
   origins, with the origin as target.
9. **No CSP, frame-ancestors or Referrer-Policy** (`cabinet/vercel.json`, and the node-served copy), while the player
   key is plain JSON in `localStorage` (`cabinet/client.js:22`, open since October). Peer `cover` still breaks out of
   `url('…')` (`app.js:671`, `:862`).
10. **`ro3.v1` is unreserved** (`cabinet/config.js:110-126`; `TitleRegistry.register` is first-come): a stranger can
    claim it and collect `cabinet:sign-key` proofs. Chain state not checked; reserve the id in config or claim it.
11. **Deploy generation 4.** In source and tested, not live: key proof-of-possession on bond, `minStake`, paginated
    directory, bounded enrol pool, `epoch < now`, exit from `Escalated`.
12. **Stake is free**: the faucet gives 1,000 tLITVM per address per day against a 1 tLITVM minimum and ~20 bonded in
    total (`contracts/TestLITVM.sol:24-30`). One pull outweighs the mesh in quorum and panel weight. Gate the faucet
    or allowlist operators before Season Zero pays anything.
13. **Escalation has never run on the live chain and its timing is wrong there.** On LiteForge (Arbitrum Orbit)
    `block.number` inside the EVM is the parent chain's (≈12.1 M) while `eth_blockNumber` is ≈69.8 M;
    `MatchBook.sol:274,285-287` counts the former and `node/matchbook.js:697,707` compares the latter to `drawBlock`,
    so the seat stagger and `seedGone` are always true. Read the EVM's number in the node and run one escalation live.
    Also: `resolve` has no participation quorum (`MatchBook.sol:304-313`, one voter decides and slashes), and the
    panel draw can be ground because the pool is read after the seed is known (`:378-389`, `:174-177`).
14. **`PlayerProfile` binds a key with no proof** (`PlayerProfile.sol:143-153`); `EpochAnchor` support can be
    recycled across re-bonded keys (`EpochAnchor.sol:96-105`); the enrol pool can be squatted with 256 minimum-stake
    keys.
15. **Transactions are not retried and three nonce managers share one key** (`node/matchbook.js:176-192`, `:661-662`,
    `node/announce.js:46-53`, `node/proxy.js:79-85`); the AIR gas sponsor is still the MatchBook delegate with no
    budget. One sender queue per key, mark after the receipt, cap sponsorship.
16. **Verifier child keeps `process` intact** (`node/verifier-child.mjs:15-22`; the title sandbox strips it at
    `sandbox-child.mjs:29`). Apply the same scrub. Not confirmed whether the runtime's permission model already denies
    network there.
17. **Mesh size:** four fresh bonded operators on the current release before any ranked claim; 13 for escalation.

**P2 — before value (stage C)**

18. Multisig behind a timelock on every admin, two-step handover; today the admin can name itself adjudicator and
    slash every bond (`NodeStake.sol:298-302`, `:309-319`). No pause on any core contract.
19. External audit of the contracts including the hand-rolled `Ed25519.sol` (RFC vectors pass; ~404k gas per verify).
20. Releases from CI, tied to a tag and a clean tree, reproducible, runtime and zip dependencies pinned by hash
    (`tools/release.mjs:38,46`, `tools/pack.mjs:38-53`), release key offline and separate from the publisher key;
    `cloudflared` pinned instead of whatever is on PATH.
21. Atomic persistence: `settle.js:137` is a bare `writeFileSync` and `readAll` (`:136`, `:152`) parses every file
    without a guard, so one torn delta after a crash or a full disk stops the node booting (D8). Same for
    `identity.json` and `release-keys.json`.
22. Reorg handling in the MatchBook scan (`node/matchbook.js:573-586`); prune `decoded`/`settled`/`panels`.
23. Pinned compiler, verified source, a mainnet config, a real token with sized stake and the 30/7/14-day terms.
24. Operations: an incident and key-compromise runbook, backup and restore steps (including AIR proxy keys),
    monitoring and alerting, a second RPC provider, a second publisher host off this machine.
