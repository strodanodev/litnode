# litnode end-to-end audit — 21 October 2026 (0.11.29, master @ 6cfff2b)

Scope: the whole checkout at `E:\NPC\AGENT 24 NODE` (317 tracked files, 170 commits since 17 Sep 2026), its four agent skills, its three harnesses, the shipped 0.11.29 zips under `dist/`, the live generation-3 contract parameters (read-only `eth_call`), and the test suite. Method: a knowledge graph of the repo (graphify, offline AST extraction, plus the repo's own `npm run graph`), five parallel read-only reviews (node daemon, protocol + contracts, SDK/tools/skills, cabinet + docs, tests), every high finding re-read at its cited line by the author, and one full `npm test` run. This is an internal review, not a third-party audit; the 17 and 20 September reviews in this folder remain the baseline and §6 says what happened to their items.

Companion: `audit/atlas-2026-10-21.html` is the interactive atlas (file graph, components, feature matrix, skills and harnesses, every finding with filters, graphify communities). `graphify-out/` holds the symbol graph and `graphify-out/graph.html` its own viewer.

## 1. Verdict

The project is a real, working testnet mesh with unusually honest documentation and a strong test culture, and it is not safe to open to strangers yet. Four daemon bugs and two cabinet bugs are reachable today by any key that can gossip, one of them turning the node's own gossip push into a request that satisfies its loopback-only update route, and another exfiltrating a player's private key from the hosted arcade through a malicious seed. Both 0.11.29 release zips ship npm scripts whose files were never packed, so the documented bonding path fails from a zip. The contracts have three design gaps that a one-wei stake unlocks. None of this is deep; all of it is the kind of thing a first external audit would lead with, and all of it is fixable in one patch release plus one contract generation.

What is strong: the result-commitment discipline (every witness recomputes one hash), the sandbox that fails closed, the release trust chain, the selector and vendoring checks that are tests rather than notes, and the in-process EVM harness that runs five real nodes through the whole MatchBook lifecycle. The feature set is wide for five weeks of work; the cost is one 1,778-line closure in the daemon and a 119 KB single-file frontend that both need splitting before the next wave of features.

Tests: see §5 for the full run on this machine.

## 4. Findings by area

Severity is the consequence on the live mesh if the scenario happens. The atlas lists all 46 with filters; the ones that change what you do next are here.

### 4.1 Node daemon

1. **High.** A gossiped heartbeat `addr` is stored raw and fetched as `${addr}/gossip` with no validation (`node/litnode.js:827`, `:915`). `addr = http://127.0.0.1:7801/update?x=` makes the node POST its gossip body to its own `/update`; `isLoopback` (`:234-238`) sees 127.0.0.1 with no forwarding headers and passes; `check()` then `apply()` then `restart()` run whenever a newer signed release exists (`:1531-1538`). Unbonded keys are accepted up to 64 and pushed every tenth tick, so no bond is needed. The same primitive reaches `/chat`, `/gauntlet/start` and `/svc/*`. Verified at the cited lines.
2. **High.** `readBody` rejects at 4 MB but never destroys the request and keeps concatenating (`:77-81`, and the inline `/gossip` reader at `:1382`): a 400 MB upload throws a RangeError into the keep-alive handler; a few in parallel exhaust the heap. Verified.
3. **High.** `POST /queue` stores the envelope before type-checking `bucket` (`NaN > 2` is false) and never checks `rulesetId` against known titles (`:1418-1425`); `queueEnvelopes` is never pruned (`:1096`). 4,096 junk entries from throwaway keys give every real player a 503 and are forwarded to every peer every tick. Verified.
4. **High.** Casual `POST /ledger` is unauthenticated, every submission spawns a sandbox child with no concurrency cap (`node/sandbox.js:41`), and every delta is kept forever in memory and on disk (`node/settle.js:109`). 200 concurrent submissions are 200 processes of up to 256 MB.
5. **Medium.** Witness binding requires the placing node to have a live heartbeat right now (`:487-491`, `:970`); a placer that restarted leaves the seats unable to attest although the chain holds the descriptor hash. Host-side binding reads only the in-memory placement, which expires after 15 minutes and on restart (`:1079`, `settle.js:118`): a long gauntlet match or a host restart voids a match the host already paid to commit.
6. **Medium.** The AIR gas sponsor is the same delegate key that pays MatchBook, with a 0.002 top-up per new AIR account and no budget (`:1690-1694`, `node/proxy.js:94-101`). MatchBook polling scans every settled match and every decoded event each 2 s (`node/matchbook.js:481-498`). Peer addresses that answer are never evicted (`:827`, `:909-917`). Any bonded key can make this node spawn title servers by naming it host (`:1185-1188`). The no-MatchBook witness path has unbounded adverts and untimed fetches that run inside the chain tick (`:1027-1066`, `:849-865`).
7. **Low.** Key rotation can retire the pinned release root automatically (`node/update.js:171-173`); anyone can trigger the update check; the catch-all returns error messages with paths and RPC URLs; `proxy.js` bids gas with no ceiling.

Structure: `createNode` is one closure holding about 40 tables and 60 functions, which is why the loopback check, the body reader and the queue validation each exist in slightly different forms. The natural seams are gossip and peer table, placement, build and bundle admission, tunnel and announce watchers, and the router plus static serving; the router should become a table so auth and limits are declared per route. The v0.2 witness path and the MatchBook path coexist behind five `mbook ?` branches; one should go. `GET /match` and `GET /fleet` mutate state because `matchesNow()` is both a view and the scheduler.

Done well: traversal-safe static serving by construction; verify-before-cache gossip with explicit ceilings; a loopback check that rejects forwarded headers (the opposite of the usual mistake); `resultFields` as the single list intake, witness and cosign share; the sandbox refusing to start without its permission flag; the release chain (pinned key, signed manifest, zip hash from the manifest, downgrade refusal, registry gate that blocks when unreadable, network-free rollback); server-bundle path rules; incident-dated hardening left in comments.

### 4.2 Protocol and contracts

The vendored cabinet copies are byte-identical to `protocol/` (17 of 17, `tools/vendor-cabinet.mjs --check` passes). All eleven deployed addresses agree across `deployed.testnet.json`, the cabinet, MIGRATION.md and the spec. Live parameters read by `eth_call` match `deploy.testnet.json` (NodeStake unbond 3600 s, MatchBook windows 1800/300/300, quorum 5000 bps, GasRefund funded with 10 zkLTC). Twenty node keys from sixteen operators hold one tLITVM each, so an epoch quorum needs five operators today.

1. **Medium.** `NodeStake.stake(nodeKey, amount)` takes no proof that the caller holds the ed25519 key and any amount above zero; the first caller is operator forever because `withdraw` never clears it (`contracts/NodeStake.sol:120-132`, `:168-181`). A node's key is public in gossip before it bonds; one wei of faucet token behind it forces the real operator to rotate identity. Verified. Not in the honest zeroes.
2. **Medium.** `NodeDirectory._keys` is append-only and `keys()` returns it whole (`NodeDirectory.sol:49-55`, `:65`); announcing needs only the one-wei operator standing above. Every node bootstrap and every arcade seed search does two `eth_call`s per key against a gateway that rate-limits at ~25 requests a second, and the arcade fails closed to "No seed has announced". Verified.
3. **Medium.** `enroll` needs only `mayActFor`, and `escalate()` loops the whole pool with an external call per entry (`MatchBook.sol:138-141`, `:330-342`); a few thousand junk enrolments push it past the gas cap and every dispute dies by expiry with nobody slashed. The pool cannot be pruned by admin.
4. **Medium.** `EpochAnchor.propose` accepts future epochs and a finalized anchor is immutable (`EpochAnchor.sol:79-97`); quorum stake can pre-finalize garbage for every future hour.
5. **Low.** No exit from `Escalated` if `resolve` reverts (fine with the mock token, not with a real one); `GasRefund.withdraw` lets the admin EOA drain the treasury and §16 does not say so; BUILD-SPEC §2.2 and §11.2 carry 15-minute unbonding and 60/120-second windows that have not been live for a month; the deploy record stores MatchBook's constructor struct as `[object Object]`; `protocol/hydration.js` is dead; keccak has no multi-block test vector; `placement.js` is the one CRLF file in the tree.

Done well: selectors and ABI shapes pinned to solc in tests; vendoring as a test; tagged signing everywhere with identity binding in the callers; MatchBook names the seed block in `finalize` before `escalate` can be called and snapshots seat weights at the draw, which closes the two September attacks by construction; exact beacon pinning that returns null rather than guessing.

### 4.3 Cabinet

1. **High.** The Ranks podium renders the full `/leaderboard` player id unescaped (`cabinet/app.js:713`; `esc()` exists at `:38`). The player's ed25519 private key is plain JSON in `localStorage` (`client.js:22`). A visitor on the hosted arcade is routed to a bonded seed by `seeds.js`, which proves the seed is who it says, not that it is honest. Verified.
2. **High.** Peer-gossiped title `display` fields are merged into `GAMES` and land in `style="--ga:…"`, `href`, `data-*` and `url('…')` unescaped (`:68-73`, `:485`, `:573`, `:557`); the node passes `display` through at `node/litnode.js:1221`. One conformant ruleset with a crafted accent executes in every cabinet on the mesh. Verified.
3. **Medium.** `short()` truncates without escaping (`:498`, `:579`, `:609`, `:629-634`); a malformed peer `display.url` throws inside the poll and skips `/snapshot` and `/fleet` for the tick (`:73`); every library card is tagged Live and the header says three titles settled on litVM while Robot Fighting Championship has no ruleset (`:318`, `:570`, `:574`); the profile claims an XP and cards sync and a tickets economy that do not exist (`:440`, `:729`); the settled-by text is hard-coded by title id so FLOOD CONTROL reads as replayed (`:603`); `chainSeeds` fans out 2×N RPC calls against the rate-limited gateway (`seeds.js:26-29`).
4. **Low.** Two level formulas on one screen; `alert()` for errors in a PWA whose own comment explains why native dialogs are avoided; a full-screen noise canvas redrawn every frame with no reduced-motion guard; portraits hotlinked from a third-party Vercel deploy.

Done well: `/fleet` is read with a fresh nonce, the digest recomputed and the node-key signature checked; a seed is trusted only after `/whoami` over https; the browser rebuilds the snapshot from signed heartbeats, recomputes placement and refuses an unproduced host; the shell signs only the match it launched and lends the AIR token only to first-party titles at their own origin; one source of contract addresses with a parse check on every served script.

### 4.4 SDK, tools and skills

1. **High.** The portable zip copies `bond-node.mjs` but not `tools/lib/rpc.mjs` it imports; the operator zip's `package.json` names `delegate`, `enroll`, `authority` and `release:registry` whose files are absent (`tools/pack.mjs:95`, `:98` vs `:103`). Confirmed in both staged 0.11.29 folders. The CLI bonding path in OPERATORS.md step 4 and host-a-node 7b fail from every zip.
2. **High.** The scheduled task runs the node with `-RunLevel Highest` (`portable/install-task.cmd:20`, `sdk/host/cli.mjs:263`), and the node executes server bundles fetched from the mesh. Publisher code runs elevated on every opted-in operator. Verified.
3. **Medium.** `restart --json` prints two JSON objects and `publish --json` up to three; `stop --force` reports success without stopping; no clock check when `SEEDS` is empty, which the operator guide recommends; `bundle-title` imports the bundled title natively after the sandbox; service status is parsed from English `schtasks` labels; `--quorum 2` survives in the runbook and wallet tool while deploy takes basis points; `init --json` prints RPC URLs that may carry keys; two `defineBalance` implementations disagree; docs say `OPERATOR_KEY` while four tools read `DEPLOYER_KEY` only.
4. **Low.** `transfer`, `params`, `release` and `bond` act without confirmation or dry-run; `mesh-check.mjs` is unreferenced and queues ranked players on a live node; launcher scripts kill by port or process name and interpolate paths into PowerShell literals; two relay key files for one bridge; `sign-build` defaults to the litVM release key.

The harnesses themselves are good. `npm run host` is the one path an agent can drive without a terminal: stages judged only by what the node and chain answer, `next --json` returning the one command to run, keys stripped from the daemon environment and `--key` refused. The bridge checks `/delta` before re-sending and explains in words why a match is not official. The test harness compiles the real Solidity into an in-process EVM and serves it over HTTP to five real nodes.

Skills: the four `SKILL.md` files are well targeted for `host-a-node` and `migrate-a-title`; `host-a-title` and `build-a-title` overlap on every developer phrasing and neither frontmatter states the discriminator (client exists vs client to be written). Each skill has at least one step that does not run as written: `npm run conformance` and `bundle:title` with no file (exit 2), `settle()` never returning `already`, `npm run bond` without its node id and with the wrong key name, `NodeStake.delegateOf` (does not exist), doctor checking cloudflared only when `TUNNEL` is already set, and `--gauntlet-servers` missing from every skill and doc. The `.agents/skills` copy is byte-identical and gitignored, so nothing syncs it. The graphify skill installed by this audit is the fifth; its project install also wrote `CLAUDE.md`, `.claude/CLAUDE.md` and a PreToolUse hook in `.claude/settings.json`, none committed.

### 4.5 Tests

Forty-nine suites in `npm test`, fifty-one on disk. `beacon.test.mjs` (the 0.11.10 exact-block invariant) and `air.test.mjs` (the whole `/air/session` flow, cited by UNIVERSAL-LOGIN.md as its proof) have never been listed; both look accidental. Thirty-six suites import `litnode.js`, so `node/` is reached transitively; `node/matchbook.js` has no unit test of its state machine, `tui.js` is never asserted, the bridge's `http` and `agent-fighter` adapters have no test, and the production release path (`pack`, `sign-build`, `release`) is untested while the updater is tested against hand-made zips. Cabinet scripts are parse-checked only, except `client`, `receipt`, `fleet`, `contracts` and `version`.

1. **High.** `stop()` never clears the 5 s update-check timer (`node/litnode.js:1767`), so the update test's node fetches its public `releaseUrl` after the test ends; the detached daemon in `host.test` runs without `LITNODE_NO_UPDATE` and can hit github.com releases during `npm test`.
2. **Medium.** The selector check in `protocol.test.mjs:29-35` only logs its disagreement (`0xbc978154` vs the spec's `0x7e8a0a8b`); the manual settle case is skipped twice and can never run; conformance scaffolds into the repo's `titles/`; fixed port ranges overlap between `host`, `gauntlet-direct` and `server-bundle`, so `--test-concurrency=1` is load-bearing, not a precaution.
3. **Low.** A `|| true` assertion, env leaked to every fake cloudflared, process-wide `dns.lookup` and `Date.now` patches, three diverging exact key-set contracts with no shared schema.

Missing negatives worth owning: a malformed or oversize ledger body; a peer on another protocol version gossiping placements; a sandbox timeout inside `/ledger`; an RPC failure between commit and settle; a bad signature at apply time or a path-traversal entry in a release zip; a forged descriptor adopted via gossip.

Done well: real contracts under test with a `logsUnavailable` mimic of LiteForge; the audit probes replayed one by one; the sandbox proved fail-closed with a planted global, a spinning title and a memory bomb; the zero-dependency signer compared with ethers byte for byte; a committed LiteForge log fixture and a synthetic month of 5,760 matches for rewards.

## 6. The September reviews, revisited

The 17 September review's eight red flags: conformance is not isolation (fixed: sandbox process, proved fail-closed); a witness can co-sign a false score (fixed: witnesses recompute `resultHash`); a labelled relay result need not come from a relay (fixed: relay keys advertised and signed over the log head); anchoring proves inclusion not correctness (superseded by MatchBook per-match finality); character registry provenance (still fixture; registry has no minter); exposed authority (rotated; the v2 key holds nothing on gen-3, but every admin is still one EOA); availability concentration (four operators, standby host documented, still one relay per title); discovery and rollout (NodeDirectory with proof of possession, ReleaseRegistry gating updates). The 20 September audit's hosting-path findings led to the host harness, which is now the strongest part of the operator story. What that audit could not have seen is what this one adds: the release zips do not ship what their scripts name, and the hosted arcade trusts a seed's content as well as its identity.

## 7. Recommendations, in order

1. **Patch release first.** Validate gossiped addresses (public http(s) origin, no path), destroy oversize bodies, type-check queue entries, authenticate casual ledgers and cap sandbox concurrency, escape every node- and peer-supplied string in the cabinet and keep the player key non-extractable. No protocol bump needed.
2. **Self-checking zips.** Derive `pack.mjs`'s copy list from the scripts map and add a test that resolves every script in each staged zip; run the operator path from a zip once per release; drop `-RunLevel Highest`.
3. **Gen-4 contracts, then the external audit.** Key proof-of-possession on `stake`, `minStake` to announce with paginated directory keys, `epoch < now` on propose, a bounded enrol pool, an `Escalated` branch in `expire`; name the GasRefund drain and the quorum-majority anchor in §16 until the multisig exists.
4. **Hermetic tests.** Clear the update timer in `stop()`, set `LITNODE_NO_UPDATE` in the harness, append `beacon` and `air`, assert the selector, scaffold into tmpdir, disjoint port ranges.
5. **One generated status.** Build §0's table and the parameters from `deployed.testnet.json` and `package.json`; prune §16 whenever §0 changes; one hostname; version stamps through `npm run version`; mark the four historical docs.
6. **Split `litnode.js`** along its five seams with a route table; delete `node/services.js`, `protocol/hydration.js` and the v0.2 witness path.
7. **Headless operator path.** `OPERATOR_KEY` accepted everywhere, `delegate` and `enroll` shipped, clock checked against the RPC `Date` header, `PUBLIC_ADDR` routability checked, `--gauntlet-servers` documented.
8. **Dry-run each skill per release** in a scratch install; split the two title skills by whether a client exists.
9. **Scale hygiene.** Index MatchBook events by match id, evict peer addresses, budget AIR top-ups.
10. **Keep the graphs current.** `npm run graph` and `graphify update .` after changes; decide whether to keep the PreToolUse hook graphify installed (`graphify claude uninstall` removes only the hook and the CLAUDE.md section).

## 7a. Patch 0.11.30 (same day)

The six high findings in §4.1 and §4.3 are closed in 0.11.30 (`CHANGELOG.md`): peer addresses must be bare origins and the node's own push can no longer pass for the operator, oversize bodies are cut off, queue entries are typed and known before they are held, unsigned ledgers are budgeted per address and pruned after a day, sandbox children are counted, and the cabinet escapes player ids and checks every peer-supplied display field. `demo/hardening.test.mjs` covers each. The zip packaging and elevated-task findings (§4.4), the contract gaps (§4.2) and the test hygiene items (§4.5) are not part of this patch.

**0.11.31 (same day, second patch).** §4.1 finding 5 is closed in both halves, and with it the hydration-test race this
review traced (`hydration.test.mjs` flaking in full runs with "ranked: no placement descriptor"; the hand-off numbered
them findings 5 and 7). The host binds a ranked ledger to the placement in its book or, once an earlier rival replaced
it, its TTL ran out or the node restarted, to the signed descriptor the client carries back from `GET /match` —
verified as the witness path verifies it, with the placing key's standing read at the descriptor's pinned block when no
heartbeat reaches it, and two checks both paths now share (the id derives from the beacon; the beacon is this node's own
for the bucket). Where the result goes is the chain's call: a commit under the ledger's id settles on chain, none
settles locally, a rival commit for the same players expires on its own. The mock chain in `demo/hydration.test.mjs`
is deterministic per height. `demo/binding.test.mjs` covers the replaced placement, the restart, the pinned-block
standing and `chain.standingAt`; `CHANGELOG.md` 0.11.31 has the detail.
